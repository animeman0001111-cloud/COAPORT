Processor Datapath Design

Overview — What is a Processor Datapath?

The processor datapath is the collection of functional units — ALU, registers, multiplexers, memory interfaces, and interconnecting buses — that physically carry out the operations specified by instructions. The Control Unit (CU) orchestrates all these units by generating control signals (Read Enable, Write Enable, MuxB_En, RZ_ALU_En, Store_En, etc.) based on the decoded opcode.

In this project's datapath simulator, a 5-stage register file (REG BANK) is connected to an ALU, a memory unit, a Program Counter (PC), and an Instruction Register (IR). Multiplexers select between register operands and immediate values. The control unit drives all enable signals to route data correctly through the pipeline for each instruction.

Key Datapath Components

  • REG BANK: Multi-port register file storing operands (RA, RB, RZ, RY, EA, RM)
  • ALU: Performs arithmetic (Add, Sub, Mul) and logical (And, Or) operations; outputs to RZ
  • MuxB: Selects between register RB value and immediate (Imm.Value) as second ALU input
  • MuxY: Selects between ALU result and memory data for write-back
  • PC: Program Counter — holds address of next instruction to fetch from Code Memory
  • IR: Instruction Register — holds the currently executing instruction's binary encoding
  • Memory: Data memory accessed for Load and Store instructions via EA (Effective Address)
  • CU: Decodes opcode from IR and drives READ, WRITE, RZ_ALU_En, MuxB_En, Store_En signals

Overview — How the Datapath Executes Each Instruction

Each instruction in the datapath follows a defined path through the components. The CU decodes the opcode and enables the appropriate control signals. Below are all seven instruction groups from the Processor Datapath Design project, with the datapath flow explained for each.

Instruction Set 1 — Load, Store, Add, Or
Set 1
Load R3, X(R1) Store R2, X(R0) Add R1, R2, R3 Or R0, R1, R2
Load: EA = R1 + X (offset). Memory[EA] → R3 via MemData_In → MuxY → RY → REG BANK. CU sets READ=1, RZ_ALU_En=0, Write_RY_En=1.
Store: EA = R0 + X. R2 → MemData. CU sets Store_En=1, READ=0.
Add: ALU(R2 + R3) → RZ → MuxY → RY → R1. MuxB selects RB=R3. ALU opcode = ADD.
Or: ALU(R1 OR R2) → RY → R0. ALU opcode = OR.

Instruction Set 5 — Load (absolute), Add, Store (absolute)
Set 5

Instruction Set 6 — Load (register indirect), And, Store (register indirect)
Set 6
Load R0, (R1) ; R0 ← Mem[R1] And R3, R4 ; R3 ← R3 AND R4 Store R3, (R5) ; Mem[R5] ← R3

Store (register indirect): EA = R5. R3 → MemData_In path. Store_En=1.

Instruction Set 7 — Load (base+index addressing), Or
Set 7
Load R3, (R1, R2) ; R3 ← Mem[R1 + R2] Or R5, R6 ; R5 ← R5 OR R6
Load (base + index): EA = ALU(R1 + R2). Both R1 and R2 are read from REG BANK. ALU computes base + index address → EA register → Memory. MemData_In → MuxY → RY → R3. MuxZ_En selects sum-of-registers mode for EA.
Or: Standard bitwise OR between R5 and R6. ALU opcode = OR. MuxB selects RB=R6.

; No instruction label — extended EA_EN datapath variant
This final circuit from the PDF introduces EA_EN (Effective Address Enable) as an explicit pipeline register control signal, replacing MUX Z EN from Sets 6 & 7. The two OPCODE comparators now drive both EA_EN and MUX_B_EN (note green LED indicators active on both comparator outputs). Code memory: 000 0ca / 366 000 / 000 000 / 000 000.
