Problem 1 — 5-Stage Pipeline with Branch Penalty

Problem Statement

Consider an instruction pipeline with five stages without any branch prediction:

  • FI — Fetch Instruction
  • DI — Decode Instruction
  • FO — Fetch Operand
  • EI — Execute Instruction
  • WO — Write Operand

Stage delays: FI=5 ns, DI=7 ns, FO=10 ns, EI=8 ns, WO=6 ns. Buffer delay = 1 ns between every two stages. A program of 12 instructions (I₁–I₁₂) is executed. I₄ is the only branch instruction with branch target I₉ — meaning I₅, I₆, I₇, I₈ are flushed. Calculate the total time to complete the program.

Solution — Clock Cycle Calculation

Clock cycle time = max{5, 7, 10, 8, 6} + 1 ns buffer = 10 + 1 = 11 ns

Clock Cycles Breakdown

  • I₁ requires 5 cycles (first instruction fills all stages)
  • I₂, I₃, I₄ = 3 cycles each (steady throughput — 1 per cycle)
  • Branch penalty (I₅, I₆, I₇ flushed, I₈ target = I₉ enters) = 3 penalty cycles
  • I₈, I₉, I₁₀, I₁₁, I₁₂ = 4 cycles (remaining instructions after branch)

Total clock cycles = 15
Total time = 15 × 11 ns = 165 ns

I₁ produces result in W stage (cycle 6). I₂ needs the value in its FO stage — must wait until after I₁'s W. This creates 2 stall cycles.

Problem 3 — Assembly Language Pipeline Hazards

Consider the assembly program:

  • I₁: Move R3, K#
  • I₂: Load R8, (R3)   ← depends on R3 from I₁
  • I₃: Add R3, #4
  • I₄: Load R9, (R3)   ← depends on R3 from I₃
  • I₅: BLE R8, R9, L3   ← branch, depends on R8 and R9

Memory access time may take 3 clock cycles. Multiple hazards exist:

  • I₂ depends on R3 produced by I₁ → RAW hazard
  • I₄ depends on R3 produced by I₃ → RAW hazard
  • I₅ depends on R8 (from I₂, memory load) and R9 (from I₄) → Load-use hazard (multi-cycle memory)

Handling strategies: pipeline stalling (insert bubbles), operand forwarding where possible, and compiler-based instruction reordering to fill delay slots.

Problem 5 — 3-Stage Pipeline, 100 Instructions

A 3-stage pipelined processor with stage delays 10 ns, 20 ns, 14 ns. No pipeline hazards.

  • Number of stages N = 3
  • Clock cycle time = max(10, 20, 14) = 20 ns
  • Pipeline latency (first instruction out) = 3 × 20 = 60 ns
  • Remaining 99 instructions = 99 × 20 = 1980 ns
  • Total = 60 + 1980 = 2040 ns
Problem 6 — 5-Stage Pipeline, 100 Instructions (with buffer delay)

Stage delays: 150 ns, 120 ns, 150 ns, 160 ns, 140 ns. Register/buffer delay = 5 ns each.

  • Clock cycle time = max(150, 120, 150, 160, 140) + 5 = 165 ns
  • First instruction out in = 5 × 165 = 825 ns
  • Remaining 99 instructions = 99 × 165 = 16,335 ns
  • Total = 825 + 16,335 = 17,160 ns

Problem 8 — Delay Bubble Elimination

Pipeline stalled: I₂ must wait for I₁'s Write stage to complete before it can proceed to Decode (D₂). I₃ and I₄ are unnecessarily delayed — the delay bubble propagates downstream.

Solution 8.4 — Parallel Decode + Write

If the Decode stage allows two Decode steps in parallel and the register file allows two Write steps in parallel, the bubble can be completely eliminated. I₃ proceeds past I₂ in the decode stage, and I₄ follows. Total cycles reduced from 8 to 7.

Pipeline Concepts in Real-Time Processors

1. ARM Cortex-A7 Pipeline — Energy-Efficient In-Order Processor

The ARM Cortex-A7 processor is built to provide a balance between performance and low power consumption. It follows an 8-stage in-order pipeline, where instructions are processed sequentially in the exact order they are received.

Key Pipeline Characteristics

  • Pipeline Structure: 8-stage pipeline
  • Execution Method: In-order execution (strict sequential)
  • Dependency Handling: Pipeline stalls when data dependencies occur
  • Branch Processing: Lightweight branch prediction mechanism
  • Power Consumption: Optimized for minimal energy usage
  • Application Areas: Smartphones, embedded devices, low-power computing systems

Pipeline Flow

Instruction Fetch → Instruction Decode → Instruction Issue → Execution (ALU) → Memory Access → Write Back

Working Example — Data Hazard in Cortex-A7

  • I₁: ADD R1, R2, R3
  • I₂: SUB R4, R1, R5  ← depends on R1 produced by I₁
  • I₃: LOAD R6, [R4]  ← depends on R4 produced by I₂

Since Cortex-A7 is strictly in-order, the processor cannot proceed until required data is available. The pipeline introduces stall cycles, temporarily pausing execution to maintain correct operation. Its strength lies in simplicity, reliability, and power efficiency — ideal for battery-powered and embedded systems.

2. ARM Cortex-A15 Pipeline — Out-of-Order High-Performance Processor

The ARM Cortex-A15 is a high-performance processor designed to maximize instruction throughput and overall system speed. Unlike simpler processors, it uses a deep 15-stage pipeline with out-of-order execution, allowing multiple instructions to be processed simultaneously.

Key Pipeline Characteristics

  • Pipeline Structure: 15-stage deep pipeline
  • Execution Method: Out-of-order execution
  • Superscalar Design: Multiple instructions execute in a single clock cycle
  • Register Renaming: Eliminates false (WAR, WAW) data dependencies
  • Branch Prediction: Advanced prediction techniques improve efficiency
  • Speculative Execution: Executes future instructions before branch outcomes confirmed
  • Performance Level: High-performance — suitable for demanding applications

Advanced Pipeline Flow

Fetch → Decode → Dispatch → Reservation Station → Out-of-Order Execution → Memory Access → Reorder Buffer → Commit / Write Back

Working Example — Out-of-Order in Cortex-A15

  • I₁: ADD R1, R2, R3
  • I₂: SUB R4, R1, R5  ← depends on I₁
  • I₃: LOAD R6, [R4]  ← depends on I₂
  • I₄: MUL R8, R9, R10  ← independent! Can execute immediately

In the Cortex-A15, I₄ has no dependency on previous instructions, so the processor executes it while waiting for I₁ and I₂ to complete. This significantly reduces idle cycles and improves overall performance. Results are committed in original program order via the Reorder Buffer (ROB) to ensure correctness.
