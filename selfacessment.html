2. Design and implement 4×4 memory using single cell memory

Introduction

A memory cell is the fundamental unit of RAM. A single static RAM (SRAM) cell stores one bit of data. By arranging such cells in rows (word lines) and columns (bit lines), we build a complete memory array. This design uses single SRAM cells to build a 4×4 = 16-bit memory — 4 locations each storing 4 bits.

Working of a Single SRAM Cell
Components
  • Two cross-coupled CMOS inverters (INV1 and INV2), forming a bistable latch
  • Two NMOS access transistors (N1 and N2), controlled by the Word Line (WL)
Ports
  • WL (Word Line): Activates the cell for read/write
  • BL (Bit Line): Carries data during write; read onto during read
  • BL̅ (Complement Bit Line): Carries the inverted data bit
Reading / Writing Process

The cross-coupled inverters make nodes Q and Q̅ complementary. When WL is HIGH, both access transistors turn ON, connecting the inverter nodes to BL and BL̅. During write, the sense amplifier drives BL/BL̅ forcefully to override the stored data. During read, the stored charge disturbs BL/BL̅ slightly, detected by the sense amplifier.

4×4 Array Operation & Conclusion

The 4×4 array has 4 rows and 4 columns:

  • A 2-to-4 row decoder takes a 2-bit address (A[1:0]) and drives one WL (WL0–WL3) HIGH at a time
  • All 4 bit lines (BL0–BL3) carry one bit each, forming a 4-bit data word
  • Write: Address selects WL; D[3:0] driven onto BL0–BL3; selected cells latch the data
  • Read: Address selects WL; cells discharge BL lines; sense amplifiers read Data_out[3:0]
Simulation Response

Write 0b1010 to address 01 → WL1 goes HIGH → cells C10–C13 written with bits 1,0,1,0. Reading address 01 → same WL1 activates → BL lines show 1,0,1,0 → Data_out = 0b1010 ✓

Conclusion

The 4×4 SRAM uses 16 single-bit SRAM cells arranged in a matrix. The row decoder selects the word line, and bit line sense amplifiers complete read/write access, forming a minimal but complete RAM module.

3. Design and implement a larger memory of size 1024×32 using 512×16 chips

Introduction

Large memory systems are built by combining smaller memory chips. A 512×16 chip has 512 addressable locations each storing 16 bits. We need to build a 1024×32 memory — 1024 locations each 32 bits wide. This requires expanding both word depth (512→1024) and word width (16→32 bits).

Design Steps
Step 1 — Determine Expansion Needed
  • Target: 1024 × 32  |  Available modules: 512 × 16
  • Width expansion: 32 ÷ 16 = 2 chips in parallel per bank (to get 32 data bits)
  • Depth expansion: 1024 ÷ 512 = 2 banks (to get 1024 addresses)
  • Total chips required: 2 × 2 = 4 chips
Step 2 — Address Partitioning
  • Total address bits = log₂(1024) = 10 bits: A[9:0]
  • A[8:0] (9 bits) → fed to all chips as row address (512 locations per chip)
  • A[9] (MSB) → fed to a 1-to-2 decoder to generate Chip Select (CS0, CS1):
    • A[9] = 0 → CS0 = 1 → Bank 0 selected (addresses 0–511)
    • A[9] = 1 → CS1 = 1 → Bank 1 selected (addresses 512–1023)
Step 3 — Data Bus Connection
  • Chip A + Chip C → provide D[15:0] (lower 16 bits)
  • Chip B + Chip D → provide D[31:16] (upper 16 bits)
  • Both chips in same bank enabled simultaneously by the same CS signal
Step 4 — R/W̅ Signal

Connected to all chips simultaneously. A single READ or WRITE accesses both chips in the selected bank, reading/writing all 32 bits at once.

Read & Write Operations
Write

CPU places A[9:0] on address bus → A[9] selects bank via decoder → A[8:0] locates row within bank → R/W̅ = 0 → D[31:0] drives 32-bit data; chip pair latches D[15:0] and D[31:16] simultaneously.

Read

CPU places A[9:0] → Decoder asserts CS for correct bank → R/W̅ = 1 → Selected chip pair drives D[15:0] and D[31:16] onto the bus → CPU reads combined 32-bit word.

Simulation Response

Write 0xDEADBEEF to address 0x200 (512 decimal → Bank 1): CS1 HIGH, A[8:0] = 0. Chip C stores 0xBEEF, Chip D stores 0xDEAD. Read back → Data bus = 0xDEADBEEF ✓

Conclusion

A 1024×32 memory is constructed from four 512×16 chips by width-expanding (chips in parallel) and depth-expanding (banks with chip-select decoding). The MSB of the address selects the bank; the remaining bits address within the bank. This technique is extensively used in practical memory subsystem design.

4. Design and implement both alternatives of a dual-ported 8-bit register file having 8 registers

Introduction

A register file is a fast internal memory inside a processor, holding a small number of registers used by the CPU during instruction execution. A dual-ported register file supports two simultaneous read operations (or one read and one write), which is essential for ALU instructions that need two source operands at the same time (e.g., Add R1, R2, R3).

Design Specification
  • Number of registers: 8 (R0–R7)
  • Width of each register: 8 bits
  • Ports: 2 read ports (RA, RB) + 1 write port (RW)
  • Address bit width: log₂(8) = 3 bits per port

Address / Port Width Table

WidthDescription
3 bitsSelect register for Read Port A
3 bitsSelect register for Read Port B
3 bitsSelect register for Write Port
8 bitsData to be written
1 bitWrite Enable
8 bitsOutput from Read Port A
8 bitsOutput from Read Port B
Alternative 1

Two separate 8-to-1 MUXes (one per read port) connected to 8 registers, plus a 3-to-8 write decoder. Both read ports operate simultaneously and independently.

Alternative 2

Shared decoder with time-multiplexed read access — smaller silicon area but cannot serve two reads in the same clock cycle.

5. Design and implement hardware for ADD instructions

(i) Add R0, R1, R2     (ii) Add R0, R1, #0x45

Introduction

In a processor, instructions are executed using a datapath, which connects the register file, ALU, and memory units. This question requires designing hardware to execute the following instructions:

  1. Add R0, R1, R2 → R0 = R1 + R2 (register operands)
  2. Add R0, R1, #0x45 → R0 = R1 + Immediate (0x45) (immediate operand)

The design must show how data flows between components and how instructions are executed step-by-step.

Design Overview — Required Hardware Components
1. Register File
  • 8 registers (R0–R7), each 8-bit
  • 2 read ports and 1 write port
2. ALU
  • Performs addition operation
3. Multiplexer (MUX)
  • Selects between register data and Immediate value
4. Code Memory
  • Stores Instructions
5. Control Unit
  • Generates control signals (MUX select, Write Enable, ALU opcode)
Block Diagram Explanation
Main Blocks 1. Code Memory
  • Outputs: Instruction word
2. Register File
  • Inputs:
    • Read address A (R1)
    • Read address B (R2)
    • Write address (R0)
    • Write Data
    • Write Enable (WE)
  • Outputs:
    • Data A
    • Data B
3. Multiplexer (MUX)
  • Input 1: Data B (from register)
  • Input 2: Immediate value (Imm)
  • Control: Select signal from Control Unit
4. ALU
  • Inputs:
    • Operand A (Data A from Register File)
    • Operand B (MUX output)
  • Outputs:
    • Result (written back to Register File)
5. Control Unit
  • Controls:
    • MUX select (0 = Register, 1 = Immediate)
    • Register write enable
    • ALU operation opcode
Tracing of Instructions — Step-by-Step Execution
Instruction 1: Add R0, R1, R2
  1. Instruction is fetched from Code Memory
  2. Register file reads:
    • R1 → Data A
    • R2 → Data B
  3. MUX selects Data B (register value) — MUX Select = 0
  4. ALU performs: Result = R1 + R2
  5. Result is written back to R0 (Write Enable = 1)
Instruction 2: Add R0, R1, #0x45
  1. Instruction is fetched from Code Memory
  2. Register file reads:
    • R1 → Data A
  3. Immediate value (0x45 = 69 decimal) is extracted from instruction word
  4. MUX selects Immediate value — MUX Select = 1
  5. ALU performs: Result = R1 + 0x45
  6. Result is written back to R0 (Write Enable = 1)
