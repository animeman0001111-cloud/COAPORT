Cache Sizes in Modern CPUs

Overview — What is Cache Memory?

Cache memory is a high-speed memory located close to the processor core. It stores frequently accessed instructions and data to reduce memory access time.

The cache hierarchy significantly improves processor performance by minimizing access to slower main memory. Because cache operates at near-CPU speeds, the processor can retrieve data in just a few nanoseconds instead of the tens of nanoseconds required to reach main RAM.

Cache Levels — Sizes in Modern Processors
Cache Level Typical Size Scope Speed
L1 Cache 32 KB – 128 KB per core Private per core Fastest (~1–4 cycles)
L2 Cache 256 KB – 2 MB per core Private per core Fast (~10–12 cycles)
L3 Cache Several MB (shared) Shared among all cores Moderate (~40–50 cycles)

Modern processors generally include all three levels. L1 is split into instruction cache (L1-I) and data cache (L1-D) in most architectures. L2 is unified and private. L3 is the last level of cache before main memory and is shared across all processor cores.

Why Cache Matters — Performance Impact

Without cache, every instruction fetch and data access would require a round-trip to main memory — taking 50–100 nanoseconds or more. At a 3 GHz clock speed, each clock cycle lasts only about 0.33 ns. This means without cache, the processor would spend most of its time idle, waiting for data.

Cache solves this with a principle called locality of reference — programs tend to access the same data repeatedly (temporal locality) and sequential memory addresses (spatial locality). Cache exploits these patterns to serve data before the processor even requests it from RAM.

  • L1 Hit: Data returned in ~1–4 clock cycles — no stall
  • L2 Hit: ~10–12 cycles — minor stall, often hidden by out-of-order execution
  • L3 Hit: ~40–50 cycles — noticeable stall
  • RAM Access (Cache Miss): ~200+ cycles — significant pipeline stall

Secondary Storage Overview

What is Secondary Storage?

Secondary storage provides permanent (non-volatile) data storage in computer systems. Unlike RAM, which loses all data when power is removed, secondary storage retains information even when the computer is switched off.

The two most common technologies are Hard Disk Drives (HDDs) and Solid State Drives (SSDs). Other examples include SD cards, USB pen drives, and NVMe drives.

HDD vs SSD — Comparison
Feature HDD (Hard Disk Drive) SSD (Solid State Drive)
Technology Rotating magnetic platters Flash memory (NAND)
Data Access Speed ~80–160 MB/s (slower) ~500 MB/s – 7 GB/s (NVMe)
Latency ~5–10 ms (mechanical seek) ~0.05–0.1 ms (electronic)
Capacity vs Cost Very high capacity at low cost Higher cost per GB, improving rapidly
Power Consumption Higher — motors spin platters Lower — no moving parts
Durability Sensitive to physical shock Highly resistant to shock
Noise Audible mechanical noise Silent operation
Preferred For Bulk archival storage OS drives, performance applications
Types of Secondary Storage Devices
  • HDD (Hard Disk Drive): Uses rotating magnetic platters and a read/write head. Offers large capacity at low cost. Access time is limited by mechanical movement (seek time + rotational latency).
  • SSD (Solid State Drive): Uses NAND flash memory chips — no moving parts. Dramatically faster read/write speeds, silent, and shock-resistant. SATA SSDs reach ~550 MB/s; NVMe SSDs reach up to 7 GB/s.
  • SD Card / MicroSD: Compact flash-based storage used in cameras, smartphones, and embedded systems. Slower than SSDs but extremely portable.
  • USB Pen Drive: Portable flash storage for file transfer. Convenient but typically slower than SSDs for sustained reads/writes.
  • NVMe Drive: Next-generation SSD interface using the PCIe bus directly, bypassing the SATA bottleneck. Offers the highest bandwidth available in consumer storage today.
Why Modern Systems Prefer SSDs

Modern computing systems increasingly prefer SSDs due to their superior performance characteristics. The speed gap between an SSD and an HDD directly affects boot times, application launch speed, file transfer rates, and overall system responsiveness.

In the context of Computer Organisation and Architecture, storage access time is a critical factor in the memory hierarchy. Slow secondary storage can become the system bottleneck — even if the CPU and RAM are fast, a slow storage drive means the OS and applications take longer to load into memory.

The principle is consistent throughout the memory hierarchy: faster storage costs more per byte but dramatically reduces access latency. From registers → L1 cache → L2 → L3 → RAM → SSD → HDD, each level is slower and larger than the one before it.
